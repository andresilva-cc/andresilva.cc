# Infrastructure — andresilva.cc

The project-owned operational source of truth for the **devops** agent. This is
the devops equivalent of `design-system.md`: the toolkit ships static devops
*rules* (`.claude/agent-rules/devops/rules/`); this file holds the project-specific
*decisions* — what is actually deployed, where, and how.

Keep it current — the devops agent reads it to understand the live system.

Single Next.js app — no separate API or worker services.

| Service | Platform | Runtime | Notes |
| ------- | -------- | ------- | ----- |
| web (Next.js 16, App Router) | Vercel | Node 24 (`.nvmrc` pins `v24.12.0`) | Server Components by default; no API routes except two `force-static` RSS route handlers (`/articles/rss.xml`, `/notes/rss.xml`). |

## Data stores

None. All content is local — static TypeScript repositories for structured data (employment history, etc.) plus MDX under `src/content/`, compiled by Velite at build time into `.velite/` (gitignored, regenerated every dev/build run). There is no database, no ORM, no migrations, and nothing to back up.

## Environment variables

The canonical inventory. Keep `.env.example` in sync with this table. Never
record secret *values* here — only names, purpose, and where the value lives.

The site needs **no environment variables to build or run**. The two that exist are optional escape hatches for local scripts, plus one required Vercel build setting:

| Variable | Purpose | Set in |
| -------- | ------- | ------ |
| `SKIP_OG_BUILD` | Skips OG image generation in `prebuild`/`pnpm og:generate` (`scripts/og/generate.mjs`). Required on Vercel — its build container is missing the system libs grafex's WebKit renderer needs, so the prebuild step exits early and the committed PNGs under `public/og/` are served instead. | `vercel.json` (`build.env.SKIP_OG_BUILD: "1"`) — checked in, not a platform secret. |
| `RESUME_PDF_PORT` | Overrides the port (default `4756`) of the throwaway `next start` server `pnpm resume:pdf` boots locally to render `/resume` with Playwright Chromium. Never used on Vercel — the resume PDF export never runs there (no Chromium binary in the build container). | Local shell only, when the default port conflicts with something already running. |

`.env.example` matches the table above: it states that no variables are required and lists these two, commented out. It previously carried `FOREM_API_URL` / `FOREM_API_KEY` from the retired dev.to integration — dev.to is now a syndication target, not a live one (`docs/architecture.md` §10) — and neither was referenced anywhere in the codebase. Both were removed alongside this file being filled in.

`APP_ENV` appears once in a `grep`-able location but only inside a fenced code sample in an article's MDX body (`src/content/articles/74-percent-performance-increase/index.mdx`) — it is prose content illustrating someone else's config, not real config for this project. Not listed above for that reason.

## CI/CD pipeline

- **Trigger**: push to `main` (production deploy), any push to a PR branch (preview deploy). No separate CI trigger — there is no `.github/workflows/` directory and no CI system distinct from Vercel.
- **Stages**: `pnpm install` → `prebuild` (`node scripts/og/generate.mjs`, short-circuited by `SKIP_OG_BUILD=1` on Vercel) → `next build`. `next.config.mjs` calls Velite's `build()` at module top level so `.velite/` exists before any import resolves it.
- **Quality gates**: none beyond a successful `next build` (which includes type-checking). No test suite, no test runner exists in this project. `pnpm lint` (ESLint flat config, `eslint-config-next` + airbnb base) is **not** wired into the Vercel build or any git hook — it runs locally and via the agent pipeline before a commit, not as a deploy gate.
- **Deploy method**: fully automatic on merge to `main` via Vercel's GitHub integration. No manual promotion step.
- **Rollback**: via Vercel's dashboard/CLI — promote a prior deployment to production. Not exercised or verified in this session.

## Monitoring & alerts

- **Logs**: Vercel's built-in function/build logs only. No external log aggregator.
- **Metrics / uptime**: `@vercel/analytics` (`@vercel/analytics/next`), wired in `src/app/layout.tsx` via `<Analytics />` in the root layout — page-view and Web Vitals tracking, zero-config (Vercel auto-detects the project). No separate uptime monitor.
- **On-call / alert channel**: none. No error-tracking or observability service (confirmed in `docs/architecture.md` §14: "No error-tracking/observability service — Vercel logs only"). Failures surface as a failed Vercel deployment or a GitHub deployment-status check, not a page.

## Operational notes

- **Two committed generated artifacts can drift from source, deliberately:**
  - `public/og/articles/*.png` and `public/og/notes/*.png` — emitted by `scripts/og/generate.mjs`, idempotent by mtime comparison against source MDX/template. Regenerate with `pnpm og:generate` after editing article/note frontmatter or the OG templates (`tools/og-article.tsx`, `tools/og-note.tsx`), then commit.
  - `public/resume.pdf` — emitted by `pnpm resume:pdf` (`scripts/resume/generate.ts`, run directly as TypeScript via Node's native type stripping). Fully manual, never wired into `prebuild` (it runs its own nested `next build` + `next start`, so wiring it in would recurse and would fail on Vercel anyway — no Chromium binary in that container). Requires poppler locally (`brew install poppler`; `pdfinfo`/`pdffonts`/`pdftotext` back the script's own validation gate before it overwrites the committed PDF).
  - Both classes of artifact exist because the tool that produces them cannot run on Vercel's build container — WebKit needs ~40 system libs the container doesn't have and won't let you `apt install`; Chromium isn't installed at all (`postinstall` short-circuits when `$VERCEL` is set).
- **Partial drift guard, not a full one.** `.claude/hooks/pre-commit-review-check.sh` is a Claude Code `PreToolUse` hook on the Bash tool — it blocks a commit made *through Claude Code* that stages resume-source changes without a re-staged `public/resume.pdf`. It does not cover commits made from a terminal, an IDE, or a git GUI, and `--no-verify` bypasses it by design. There is no git hook and no CI check enforcing this — closing that gap is an open decision, not yet made (see `docs/architecture.md` §11).
- **No auth, no secrets rotation surface.** No auth provider, no payments, no email, no CMS, no third-party API keys in current use (the `.env.example` entries noted above are stale). The lowest-risk area of the whole stack from a supply-chain/secrets standpoint — the only "secret-shaped" thing on Vercel is the non-secret `SKIP_OG_BUILD=1` build env var.
- **`vercel.json` is the only platform config file in the repo** (`build.env.SKIP_OG_BUILD`). No `Dockerfile`, no `docker-compose.yml`, no IaC — the platform is fully managed by Vercel's zero-config Next.js detection.
